# 设计与实验口径

## 组件边界

`ingest.py` 只负责文本与来源，`retrieval.py` 只负责索引和排序，`answer.py` 只负责拒答与原文输出，`evaluate.py` 处理实验协议，`report.py` 处理展示。当前没有外部 LLM provider，回答模式字段固定为 `offline-extractive`。

索引在内存中重建，不序列化 pickle，不需要向量数据库。Markdown chunk 导出为可审计的 JSON；该 manifest 是来源清单，不是可直接加载的检索索引。

## 切块与 ID

默认上限 320 字符，相邻切块重叠一个原始行片段。正常行按原文行边界累计；单行超过预算则按字符切开，所有片段引用同一个原始行号。大于切块本身的 overlap 仍至少向前推进一片，避免死循环。

ID 为 `SHA256(relative_path + line_start + line_end + text)[:16]`。这是短摘要标识，理论上存在哈希碰撞，未提供对抗式唯一性保证。文件移动或内容改变会改变 ID。空文件不生成 chunk，UTF-8 BOM 被正常移除，根外符号链接不加入语料。

## 排序公式

BM25 使用正 IDF：`log(1 + (N - df + 0.5) / (df + 0.5))`，长度归一化参数 `k1=1.5, b=0.75`。对 query 的唯一词项累加分数，英语仅小写与停用词过滤，中文按连续汉字段的二元字串处理；不做语义同义扩展。

字符 TF-IDF 使用 2–4 元组、sublinear TF 与 L2 归一化。归一化向量点积为 cosine。词表仅拟合当前文档语料，没有使用问题或 qrels 拟合向量化器。

RRF 融合每路前 50 个正分候选，按 `sum(1/(60+rank))` 计分，rank 从 1 开始；平局按 chunk ID 排序。它混合排名而不是 raw scores，无法创造两路都漏掉的相关结果。

## 拒答与回答

拒答启发值是**当前方法排名第一的 chunk 的字符 cosine**，不是 RRF 分数，不是概率。三个排序方法可以返回不同的 top1，所以分别使用 dev 选择阈值。若没有正分候选，即使阈值为零也拒答。

接受后展示前两个候选 chunk 的精确原文，保留完整候选供报告检查。没有事实抽取、蕴含分类器、query rewriting 或 LLM synthesis。当前判断缺少问题所要求的属性槽位，因此会接受“主题相近但没有答案”的资料。

默认 query 命令阈值 0.16 是演示操作值；evaluate 单独选择阈值，结果写进 metrics.json。报告复现需用结果中的阈值，而不是把 CLI 默认值误认为同一个 operating point。

## 评测协议

- qrels 是二值**文档级**相关性。先检索所有可用候选，再按第一次出现去重来源，再截取 k 个不同文档。
- Recall@k = 命中的相关文档数 / 相关文档数；MRR 只计算第一个命中；nDCG 使用二值 relevance 与 log2 排名折扣。
- 无答案问题不加入排序指标平均，避免无相关文档时定义含混。拒答单独报告 TP/FP/TN/FN，正类表示可回答／接受，不表示答案正确。
- 阈值候选来自 dev 相似度断点。先最大化 balanced accuracy，再最大化 F1，再选更高阈值。test 不参与这个过程。
- 记录代码依赖版本、语料和问题文件 SHA256、切块参数、候选深度。UTC 时间与延迟会随运行变化；排序和标签统计在相同环境与数据下应保持稳定。
- 热索引延迟包含两次搜索（文档排序与原文回答），不包含建索引、网络、服务调度或语言模型。它不能表示线上端到端 SLA。

## 规模与复杂度

当前 BM25 每个 query term 扫描全部 chunk，约 O(|q|·N)，TF-IDF 使用稀疏矩阵点积，排序实现约 O(N log N)。索引开销随语料词项和字符 n-gram 数增长。它适合小语料、排错和基线实验，不适合直接承接百万文档请求。

扩大规模应优先增加倒排索引、候选剪枝、增量索引、索引版本管理、访问控制、按权限过滤、并发与服务压测。再根据真实 qrels 比较语义 embedding、cross-encoder 与 sparse hybrid 的边际收益；不是仅替换一个向量库名字。

## 已知不足

1. 演示资料、问题、qrels 来自同一作者，规模很小；拆分 query 不等于跨领域独立评测。
2. 同主题未知问题拒答弱，当前实测 false accept rate 50%，需要更有针对性的 dev 数据和证据支持检测。
3. 文件级相关性不表示每个 chunk 都包含完整答案，需添加段落级 qrels 与事实支持标注。
4. 没有学习式重排或生成模型；没有声称测试过真实 API、token 成本或并发吞吐量。
5. 本地 CI 仅验证逻辑与回归；依赖允许范围不是完整 lockfile。正式复现实验应在固定环境中运行并保留版本输出。

未来评估应先固定新资料与真实问题集、留出未接触过的 test，再选择增强方案。不能看到当前 test 失败后反复调规则，还把同一份 test 当独立证明。
